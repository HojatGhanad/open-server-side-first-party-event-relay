First-party server-side tracking for GA4 and Google Ads

Open Server Side First Party Event Relay is a free, open-source relay for Google's official server-side Tag Manager. Your events travel through your own domain, on a server you control, so ad blockers, short-lived cookies and wrong geolocation stop eating your conversion data. 📡

What client-side tracking quietly loses

The tag still fires and the dashboard still fills up. The gaps only show when you compare GA4 with your orders.

The leakWhat the relay does
🚫 Blocked requests

Ad blockers and privacy extensions block google-analytics.com and googletagmanager.com. Those conversions never reach GA4 or Google Ads bidding.

🏠 Your own domain

Events go to a path on your site, like /metrics. Optional protected transport also changes the request shape, so generic path rules do not match.

🍪 Cookies that expire in days

Safari's Intelligent Tracking Prevention caps cookies written by JavaScript to 7 days. Returning customers start to look like new ones.

🔒 Server-set first-party cookie

sGTM sets an HTTP-only FPID cookie from your own host, in a true first-party context.

🌍 Everyone lives in your data center

A careless proxy sends your server's IP to Google, and every visitor is geolocated to one city.

📍 Real visitor IP forwarded

The relay passes the visitor's IP, host and scheme to sGTM, so GA4 reports the right country and city.

How it works

The relay is a thin layer in front of Google's own server container. Your GTM tags, clients and templates stay exactly as they are.

  1. Tag points home

    Your Google tag uses server_container_url set to a path on your own domain.

  2. Proxy hands off

    nginx, Caddy or your CDN routes that path to the relay on the same server.

  3. Relay forwards

    It finds the site by hostname, forwards the request with the visitor IP, and returns the first-party cookie.

  4. sGTM delivers

    Google's server container runs your tags and sends the data to GA4, Google Ads and more.

Features

Small enough to read in an afternoon, complete enough to run many sites from one box.

🛡️

Protected transport

The relay prepends a small script to the tag loader. GA4 requests to your collect path are wrapped in an opaque envelope and posted to a random path unique to your site. The relay unwraps them, so sGTM receives the original request. If the script ever fails, the standard path keeps working.

🧠

Google's official sGTM inside

No new SDK and no new schema. Keep using Tag Manager and its template gallery.

🏢

Many sites, one deployment

Each hostname gets its own routing, keys and sGTM target in tenants.yml.

🔁

Changes without restarts

Edit the routing table and the relay reloads it within seconds.

📦

First-party tag loader

Serve the GTM loader from your domain, under a path that looks like your own assets.

🔍

Built-in debugging

Health, summary and per-event traces for your own browser, plus GTM Preview routing.

🖥️

Operations panel

Live and historical traffic per site, delivery rate and latency, with tenant editing in the browser.

Quick start

You need a Linux server with Docker, a site on HTTPS, and a Google Tag Manager server container. Full guide.

  1. Configure

    Paste the container config from Tag Manager and pick a debug token.

    git clone https://github.com/HojatGhanad/open-server-side-first-party-event-relay.git
cd open-server-side-first-party-event-relay
cp .env.example .env
cp tenants.example.yml tenants.yml

  2. Start

    The relay and two sGTM containers come up on your server.

    docker compose up -d
docker compose ps

  3. Route and point

    Send a path on your site to the relay, then set it as the tagging server URL.

    location /metrics/ {
  proxy_pass http://127.0.0.1:8090;
  proxy_set_header X-Forwarded-For
    $proxy_add_x_forwarded_for;
}
# Google tag: server_container_url =
# https://your-domain.com/metrics

Deployment options

Same-origin recommended

shop.example.com/metrics/

Longest cookie lifetime in every browser, no CORS, no extra certificate.

Subdomain

metrics.shop.example.com

When you can only add a DNS record. Safari may cap the cookie at 7 days.

CDN path routing

/metrics/* → relay origin

For sites behind a CDN that supports per-path origins.

🌍

Works in restricted networks. The relay was developed and tested on networks where public container registries may be unreachable, including in Iran. Ship images over SSH with the included script, build through a Docker Hub mirror, or route the collect path through a regional CDN such as ArvanCloud.

The server running sGTM still needs outbound access to Google's collection endpoints.

Questions

Is this a replacement for server-side Google Tag Manager?

No. It runs with Google's official sGTM container. The relay handles first-party routing, visitor IP forwarding, multi-site configuration and protected transport. sGTM runs your tags.

Is it a free alternative to Stape?

It covers the same core use case, first-party server-side tagging for GA4 and Google Ads, as an open-source project you host yourself. Stape is a managed service with a broad catalogue of add-ons and support. If you would rather not operate a server, a managed service is a good choice.

Does it work with Google Ads conversion tracking?

Yes. Google Ads tags run inside your sGTM container as usual. The relay only changes how events reach sGTM.

Will GA4 show the correct visitor location?

Yes, as long as your reverse proxy sets X-Forwarded-For. The relay forwards the visitor IP to sGTM, which passes it to Google for geolocation. Check the country in GA4 Realtime after setup.

Does it bypass ad blockers?

First-party routing avoids blocklists that target Google's domains, and protected transport avoids generic rules that match Google's request paths. No technique is guaranteed against every blocker or future filter rule.

Can I run several websites on one server?

Yes. Add one block per hostname to tenants.yml. Each site can have its own sGTM target, keys and paths, and changes apply without a restart.
